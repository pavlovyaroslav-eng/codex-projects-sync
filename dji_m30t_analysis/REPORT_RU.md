# Отчёт: DJi Battery Killer и поддержка TB30 / bq76930

Дата анализа: 2026-08-12. Исследуемые бинарники не запускались. Динамическая работа с батареей, прошивка, стирание памяти, снятие защит и изменение регистров BMS не выполнялись.

## Результат

Исходная программа декомпилирована локально до IL и реконструированного C# с помощью ILSpy 9.1.0.7988. Прямой бинарный патч не выбран: приложение является смешанной 32-битной C++/CLI-сборкой, а его логика жёстко рассчитана на Smart Battery/BQ30Z55/BQ9003/BQ9006. Добавление строки `bq76930` в интерфейс не обеспечило бы совместимость и могло бы отправить команды BQ9003 в несовместимый AFE.

Вместо этого создан независимый модуль `Tb30Bq76930Diag.exe`, использующий те же официальные DLL Silicon Labs CP2112. Модуль предназначен для безопасного первого этапа поддержки Matrice 30/TB30: прямой read-only доступ к регистрам bq76930, автоопределение адреса/CRC, калибровка ADC, напряжения ячеек и пакета, статусы и сырой coulomb-counter.

## Что установлено о DJIBatteryKiller.exe

- Константа адреса батареи равна десятичному `22`, то есть CP2112 write-address `0x16`, соответствующий стандартному 7-битному Smart Battery address `0x0B`.

## Архитектурное различие bq76930

По документации Texas Instruments bq76930 — это AFE/monitor для 6–10 последовательных Li-ion/LiFePO4 ячеек, а не полноценный Smart Battery gas gauge. Он работает как I2C slave до 100 kHz. Варианты имеют:

- 7-битный I2C address `0x08` либо `0x18`;
- LDO 2.5 V либо 3.3 V;
- CRC выключен либо включён;
- 30-TSSOP корпус.

Конкретный orderable suffix по сокращённой маркировке `bq7693…` не подтверждён, поэтому драйвер проверяет оба адреса и CRC. У bq769x0 нет читаемого регистра уникального part ID, поэтому ответ определяется как «совместимая карта bq769x0», а не как криптографически подтверждённый bq769300x.

Официальные параметры TB30: Li-ion 6S, 5880 mAh, 26.1 V, 131.6 Wh. Для 6S-конфигурации bq76930 физические ячейки ожидаются на каналах `VC1`, `VC2`, `VC5`, `VC6`, `VC7`, `VC10`; остальные каналы должны быть закорочены по схеме TI.

В реальной TB30 между внешним разъёмом и bq76930 может находиться отдельный MCU. В таком случае прямой AFE-драйвер будет работать только на тестовых точках SDA/SCL самого bq76930, а для внешнего разъёма потребуется отдельное документирование протокола MCU. Одного фото AFE недостаточно для восстановления этого уровня.

## Новая программа

Исходник: `src/Tb30Bq76930Diag.cs`.

Сборка: `dist/Tb30Bq76930Diag.exe`.

SHA-256 EXE: `4341BF9C9BD30F123C0A6FEF636D2B514FE026A098C678B5DEEADA20DC17484A`.

Свойства безопасности:

- отсутствует импорт/вызов `HidSmbus_WriteRequest`;
- нет команд записи регистров батареи;
- нет unseal/FAS/PF reset;
- нет загрузчика прошивки;
- нет сетевого кода и запуска внешних процессов;
- VID/PID по умолчанию ограничены CP2112 `10C4:EA90`;
- перед конфигурацией проверяется CP2112 part number `0x0C`;
- нулевые VID/PID и открытие произвольных HID запрещены.

Собирается как x86 .NET Framework 4.8, потому что приложенные DLL CP2112 — 32-битные.

## Проверка

- Компиляция `csc.exe 4.8.4084.0`: успешно.
- Offline self-test CRC-8 polynomial `0x07` и карты 6S: успешно.
- Перечисление CP2112 с фильтром `10C4:EA90`: найдено 0 устройств; аппаратный тест не выполнялся.
- Microsoft Defender custom scan с `-DisableRemediation`: исходный пакет — угроз не найдено; новый EXE — угроз не найдено; exit code `0`.
- Исходник статически проверен: вызовов записи в SMBus, сети, реестра и запуска процессов нет.

## Ghidra

В текущей сессии MCP-инструменты `ghidra/*` не были предоставлены, поэтому обязательный вызов `ghidra/list_project_binaries` технически не мог быть отправлен. Попытка подключиться к станции для предусмотренного staging завершилась локальным exit code `124` и точным сообщением SSH:

`ssh: connect to host 10.93.0.10 port 22: Connection timed out`

Поэтому декомпиляция выполнена локально ILSpy. Файлы не запускались ни на Acer, ни на Ubuntu-хосте.

## Что нужно перед аппаратным тестом

1. Полное фото платы с обеих сторон, читаемая маркировка всех крупных IC, особенно отдельного MCU/gauge.
2. Подтверждённые тестовые точки `GND`, `SDA`, `SCL`, измеренное напряжение pull-up и отсутствие прямого соединения с силовыми контактами.
3. Полный suffix bq76930 либо результаты автоопределения адреса/CRC.
4. Номинал шунта для пересчёта coulomb-counter в ток.
5. Лог read-only диагностики. Только после него можно проектировать следующий этап; изменение защит и прошивка остаются отдельными опасными операциями и требуют отдельного подтверждения.
