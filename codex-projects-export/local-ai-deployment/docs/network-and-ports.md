# Сеть и порты

Фактический Ethernet link на Ubuntu согласован как `100Mb/s Full Duplex`. Драйвер
Realtek `r8169` работает, ошибок AI-служб из-за сети нет; предел около 10–11 MiB/s
при загрузке моделей соответствует физическому link. Для ускорения копирования
моделей проверить кабель, порт коммутатора/роутера и автосогласование 1 GbE.

| Порт | Служба | UFW source | Публичный доступ |
|---:|---|---|---|
| 22/tcp | OpenSSH | `192.168.1.41/32`; `10.93.0.0/24` on `tun93` | нет |
| 3000/tcp | Open WebUI | `192.168.1.41/32`; `10.93.0.0/24` on `tun93` | нет |
| 8000/tcp | PyGhidra MCP в LLM mode; Whisper API/Web в whisper mode | `192.168.1.41/32`; `10.93.0.0/24` on `tun93` | нет |
| 8080/tcp | Qwen OpenAI/tool-call compatibility proxy → `127.0.0.1:8012` | `192.168.1.41/32`; `10.93.0.0/24` on `tun93` | нет |
| 8188/tcp | ComfyUI | `192.168.1.41/32`; `10.93.0.0/24` on `tun93` | нет |

Службы слушают LAN/VPN для удобства, но UFW отсекает все остальные источники.
VPN-контрольная точка применена: `tun93`, `10.93.0.0/24`, без default route,
DNS и NAT. Широкое правило для `192.168.1.0/24` не используется.

PyGhidra слушает только loopback `127.0.0.1:8000`; отдельный socket proxy
публикует MCP лишь на VPN-адресе `10.93.0.10:8000`. Whisper в своём режиме
занимает `0.0.0.0:8000`. `ai-mode` и взаимные systemd `Conflicts` исключают их
одновременный запуск.
